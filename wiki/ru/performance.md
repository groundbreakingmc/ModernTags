# Производительность

Стоимость зависит от того, что показывают теги. Сделать те же теги дешевле нечем, но несколько
решений меняют, сколько работы они дают.

## Плейсхолдеры зрителя

Возьмём 50 игроков, которые все видят друг друга, например на спавне или на ивенте.

- `"{owner:name} &c❤ {owner:health}"` одинаков для всех зрителей, поэтому вычисляется один раз
  на владельца: 50 раз.
- `"{owner:name} &7пинг {viewer:player_ping}"` у каждого зрителя свой, поэтому вычисляется для
  каждой пары: 50 × 49 = 2450 раз, почти 50².

Одного `{viewer:...}` или `{rel:...}` достаточно, чтобы тег попал во второй случай. Если такой тег
нужен только части зрителей, выдайте его им отдельной записью, как в
[примере для персонала](examples.md#дополнительная-информация-для-персонала).

## Интервалы обновления

- `placeholders-update-rate`: интервал побольше для дорогих плейсхолдеров PlaceholderAPI, `-1`
  для текста, который не меняется. Зрителям отправляется только изменившийся текст.
- `frame-update-rate`: каждая смена кадра отправляется всем зрителям, так что медленная анимация
  даёт меньше трафика.
- `conditions-recheck-rate`: каждая перепроверка вычисляет условия всех игроков онлайн.
  `hasPermission` дешёвый, плейсхолдер PlaceholderAPI стоит столько, сколько его расширение.

## PlaceholderAPI вне основного потока

Плейсхолдеры и условия вычисляются вне основного потока сервера. Расширения, которые только читают
данные, там работают нормально. Расширения, которые меняют мир или хранят состояние без
синхронизации, в теги лучше не ставить.

Хотя если вам попались такие плейсхолдеры, лучше удалить сам плагин: плейсхолдеры изначально
предназначены только для чтения или сравнения данных и никогда для изменения.
